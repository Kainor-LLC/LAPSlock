Sign-in error glossary

Built from the glossary inside the app

What this is

The error codes Microsoft Entra returns when a sign-in fails, in plain English, with what to do about each. TenantKeep On-Call shows the same line beside every failed sign-in in its Sign-in triage module, so the person on call gets the answer without a search. This page is the same glossary, published for everyone.

Each code links directly: add #50074 to the address to share one entry. Microsoft's full reference is the authority; this is the one-line version for 2 am.

Codes

CodeWhat it meansWhat to do
0 Success
The sign-in succeeded.		 Nothing to fix here. If the person still cannot get in, the problem is after sign-in: a licence, an app assignment, or the app itself.
50053 Account locked
Too many wrong passwords, or Microsoft locked the account after seeing a pattern it associates with attackers.		 If the person was not trying repeatedly, treat it as an attack and look at the source IP before unlocking. Otherwise wait for the lockout to clear or unlock the account in Entra.
50055 Password expired
The password has passed its expiry date.		 Reset or change the password. Check the password policy if this is a surprise.
50056 No password or invalid password
The sign-in arrived with no password or an unusable one. Common with federation or single sign-on misconfiguration.		 Check the federation or SSO setup for this user's domain rather than the password itself.
50057 Account disabled
The account is disabled in Entra.		 If that was not intended, enable it. If it was, the person should not be trying to sign in.
50058 Silent sign-in interrupted
An app tried to sign in without showing anything and Entra needed the person to interact.		 Usually harmless. The app shows a prompt next and the sign-in completes. Only investigate if it repeats without a successful sign-in after it.
50072 MFA registration required
The person has to register for multifactor authentication before continuing.		 Have them complete MFA registration. If a registration campaign or policy is new, expect many of these.
50074 Strong authentication required
A policy required a second factor and this sign-in did not provide one yet.		 Expected once, as the first prompt. If it repeats without a success after it, the person is cancelling the prompt or their method is broken.
50076 MFA required again
Entra asked for a second factor because something changed: a new device, a new location, or an administrator changed MFA settings.		 Expected after a change. If nothing changed and it keeps happening, look at the device and location on the sign-in.
50079 MFA registration required
The person has to register a multifactor authentication method before this app will let them in.		 Have them register a method, then sign in again.
50097 Device authentication required
A policy requires a known device and this sign-in came from one Entra does not recognise.		 Register or join the device, or sign in from a device that already is.
50105 Not assigned to the app
The app requires assignment and this person is not assigned to it.		 Assign the person, or a group they are in, to the enterprise application.
50126 Wrong username or password
The username or password did not match.		 Have them try again carefully. Many of these in a short time from one address is a password spray, not a typo.
50131 Blocked by Conditional Access
A Conditional Access policy blocked the sign-in, often a location or device rule.		 Read the applied policies on this sign-in. The one marked as failed is the reason.
50133 Session no longer valid
The password was changed or reset, which invalidated existing sessions.		 Sign in again. Nothing to fix unless the change was not expected.
50140 Keep me signed in prompt
The sign-in paused on the stay signed in question.		 Harmless. The person answers the prompt and continues.
50144 On-premises password expired
The Active Directory password has expired and the sign-in was validated against it.		 Change the password in Active Directory, then let it sync.
50155 Device authentication failed
The device tried to prove itself to Entra and could not, usually a broken device registration or certificate.		 Re-register the device, or check its join state in Entra and Intune.
50158 External security challenge not satisfied
A third-party MFA provider or an authentication strength requirement was not met.		 Check the external MFA integration, or the authentication strength on the policy that applied.
50173 Fresh sign-in required
The token the app held has expired or been revoked and a new sign-in is needed.		 Sign in again. If sessions are being revoked unexpectedly, check for a sign-in frequency policy.
50199 Confirmation needed
Entra asked the person to confirm the sign-in was really them, for example when switching organizations.		 Harmless. They confirm and continue.
53000 Device not compliant
A Conditional Access policy requires a compliant device and Intune reports this one as not compliant.		 Open the device in Intune and see which compliance setting failed. That setting is the fix.
53001 Device not domain joined
A policy requires a Microsoft Entra hybrid joined device and this one is not.		 Join the device, or sign in from one that is.
53002 Device not registered
A policy requires a registered or managed device and this one is neither.		 Register or enrol the device, then sign in again.
53003 Blocked by Conditional Access
A Conditional Access policy blocked this sign-in outright.		 The applied policies on this sign-in name the one that blocked it. Fix the condition or exclude the person, deliberately.
53004 MFA registration required
The person must finish registering for multifactor authentication before this content opens.		 Have them complete registration.
65001 Consent missing
The app needs permissions this person or organization has not consented to.		 Grant admin consent for the application, or let the person consent if that is allowed.
70044 Session expired
The refresh token expired, so the app has to sign in again.		 Sign in again. A short session lifetime policy will cause more of these.
81010 Seamless SSO failed
The Kerberos ticket used for seamless single sign-on was invalid or expired.		 The next sign-in falls back to a normal prompt. Investigate only if seamless SSO fails for everyone.
90072 Account not in this organization
The account belongs to another organization and has not been invited here.		 Invite the person as a guest, or have them pick the right organization at sign-in.
500121 MFA not completed
The second factor failed: it timed out, was denied, or the code was wrong.		 If the person did not start this sign-in, treat it as push bombing and look at the source. Otherwise have them retry with their method ready.
530032 Blocked by a security policy
A Conditional Access policy with a security control, such as an authentication strength or a risk condition, blocked the sign-in.		 Read the applied policies. If it is risk based, check the person's risk state.
700016 Application not found
The application ID in the request does not exist in this organization.		 The app is misconfigured or pointed at the wrong tenant. Not a user problem.
7000218 Public client flow required
The app sent a request that needs either a client secret or the public client setting on its registration.		 Enable public client flows on the app registration, or fix the app's authentication code. Not a user problem.
Missing one? The glossary grows from real tickets. If a code you meet is not here, send it with one line about what fixed it and it goes in the next release of the app and this page together.
