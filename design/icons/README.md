# LAPSlock icon and wordmark

Everything in this directory is generated by `render-icon.py`. There is no design file.
That is deliberate: a script can be diffed, reviewed, and re-run at any size years from
now, and it cannot be lost when someone's design tool subscription lapses.

```
python3 design/icons/render-icon.py <outdir>
```

Requires Pillow. No other dependencies.

## The mark

A **keycap with a keyhole**, light on a navy field.

The name reads as a keyboard key — LAPS lock, Caps Lock — so the icon is the artifact
this product's buyers touch all day. A bare padlock was the obvious alternative and was
rejected: every security app on the App Store is already a padlock, it says nothing
specific about this product, and it is close to impossible to protect as a design mark.

One shape with one hole is the whole idea. The keycap says keyboard, the keyhole says
credential, and nothing else competes. A padlock variant was built and compared at real
device sizes; at 29x29 its shackle, body and keyhole merged into a dark blob while the
keyhole version stayed legible. `draw_padlock` is still in the script if that comparison
ever needs redoing.

The keyhole also carries over from the previous icon, so the brand does not restart from
zero on the rename.

### Why the keycap has an asymmetric bevel

Thin at the top, thick at the bottom, so it reads as a key seen slightly from above. A
uniform border reads as a frame or a badge, not a keycap. This was wrong in the first pass
and is the single detail that makes the silhouette work.

## Palette

| Name | Hex | Use |
|---|---|---|
| Navy | `#16233A` | icon field, the keyhole itself |
| Steel | `#4A6E96` | keycap side walls, LAPS in the wordmark |
| Cap | `#EEF3F8` | keytop |
| Ink | `#1A1A1A` | lock in the wordmark |

Steel is taken from the original hand-drawn wordmark so the icon and the wordmark belong
to each other rather than merely coexisting.

## Outputs

| File | Goes where |
|---|---|
| `AppIcon.appiconset/` | replaces the set in `App/lapslock/lapslock/Assets.xcassets/` |
| `entra-logo-215.png` | Entra app registration, Branding & properties |
| `wordmark-inline.png` | site header, README |
| `wordmark-stacked.png` | tighter spaces where the inline lockup will not fit |
| `AppIcon-LAPSlock-keyhole-1024.png` | loose copy of the shipping icon |
| `proof-strip-*.png` | not shipped, see below |

The asset catalog ships a **single 1024 image**. Xcode 14 and later derive every other
size from it, so shipping one file is correct and one fewer thing to keep in sync.

Icons are written as RGB with **no alpha channel**. The App Store rejects an icon that has
one.

## The proof strips

`proof-strip-keyhole.png` renders the icon at 180, 120, 87, 60 and 29 points, which are
the sizes iOS actually draws. They are not shipped; they exist so a human can judge the
mark at the sizes it will really be seen at.

Judging an icon at 1024 is how you ship something that is mud on a home screen. Regenerate
and look at the strip after any change to the mark.

## The Entra logo is not optional

`entra-logo-215.png` is the image on the **consent screen** — the moment an administrator
decides whether to grant read access to every local administrator password in their
tenant. That single screen is the largest threat to this product, larger than price or
marketing.

215x215 PNG, under 100 KB. Uploaded at Entra admin center → App registrations → LAPSlock →
Branding & properties. It applies immediately, with no build and no release, so there is
never a good reason for it to be missing.

## Changing the mark later

Cheap, on both surfaces. The app icon is PNGs in an asset catalog and ships with any
ordinary app update. The Entra logo is a single upload that takes effect instantly.

Neither is a decision that has to be got right the first time, unlike the bundle
identifier and the App Store name.
